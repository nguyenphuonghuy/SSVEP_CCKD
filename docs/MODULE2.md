# Module 2 acceptance criteria
1. `models/cckd_backbones.py`, `training/kd_losses.py`, `training/cckd_pipeline.py` implement CCKD (teacher 9C → student 3C/1C, multi-level relational KD) faithfully to the verified reference (`ssvep_ensemble`); teacher accuracy reproduces the reference (~64–66% Benchmark, ~53–54% BETA) before any student/KD run is trusted.
2. `training/train_cckd.py` produces one timestamped JSON per run under `results/module2/<run_name>/`; no result is hand-edited — every number quoted in the paper traces back to one of these files.
3. Main comparison (FB-tCNN, fixed subject-independent split, 3 seeds) covers Benchmark + BETA, both student configs, and the four KD strategies (baseline, response, response+relational, proposed relational), with per-subject Wilcoxon paired stats.
4. Backbone-generalization check (EEGNet) is not accepted on a single default hyperparameter: a negative/neutral result triggers (a) a $\lambda_{sp}$ sensitivity sweep and (b) an alternative-strategy sweep (response-based, hybrid), with any promising candidate re-run at a larger seed count before being called significant — guards against both "unlucky hyperparameter" and multiple-comparisons false positives.
5. Real-time feasibility claim (Raspberry Pi 4) is backed by an actual SSH-deployed run on the physical device, not a simulation — 7 independent process runs with inter-run cooldown, reported as mean ± 95% CI.
6. `paper/latex/main.tex` contains no fabricated or mismatched numbers: every table is periodically cross-checked against its source JSON in `results/module2/`.
